## Bug Reports

Found a bug? Open an issue on the relevant repository:

| Repo | Link |
|---|---|
| Contract | [github.com/yourusername/stellarnotify-contract/issues](https://github.com/yourusername/stellarnotify-contract/issues) |
| Backend | [github.com/yourusername/stellarnotify-backend/issues](https://github.com/yourusername/stellarnotify-backend/issues) |
| Frontend | [github.com/yourusername/stellarnotify-frontend/issues](https://github.com/yourusername/stellarnotify-frontend/issues) |
| Docs | [github.com/yourusername/stellarnotify-docs/issues](https://github.com/yourusername/stellarnotify-docs/issues) |

When opening an issue, include:
- Clear description of the problem
- Steps to reproduce
- Expected vs actual behavior
- Relevant logs or error messages
- Your environment (testnet/mainnet, Stellar CLI version, Node.js version, etc.)

## Security Vulnerabilities

**Do not open a public issue for security bugs.**

Email security-sensitive reports to:

📧 **security@stellarnotify.dev**

See the [Security Model](./security) page for the full responsible disclosure policy. We aim to respond within 48 hours and will credit reporters in the changelog once a fix is released.

## Feature Requests

Have an idea for a new feature? Open an enhancement request on GitHub with the `enhancement` label. Community votes help prioritise what ships in the next release.

See the [Roadmap](./roadmap) for features already planned for v0.2 and v0.3.

## Documentation Feedback

Spotted a typo, broken link, or unclear explanation? Open a PR or issue on the [stellarnotify-docs](https://github.com/yourusername/stellarnotify-docs) repo. Contributions to docs are welcomed and reviewed quickly.
